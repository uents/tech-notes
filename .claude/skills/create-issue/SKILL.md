# create-issue

## 1. 既存のイシューを確認する

- `gh issue list --state all` で、同じ内容のイシューがないか確認する。

## 2. 本文を書く

- 日本語で、1文1行で書く。
- 次の見出しを使う。当てはまらない見出しは省く。

```markdown
## 目的

<何のために、何をするか>

## 位置付け

<親イシューや他のイシューとの関係>

## やること

- [ ] <作業>

## 注意

<ライセンス、他人のリポジトリの扱い、前提など>

## 完了条件

- <確認できる形で書く>

## 参考

- <関係するドキュメント、PR、URL>
```

- 確認していないことを事実として書かない。未確認のことは未確認と書く。

## 3. 作成する

- タイトルは日本語で、何をするかが分かるように書く。
- 作成する前に、タイトルと本文をユーザーに見せて確認をとる。

```bash
gh issue create --title "<タイトル>" --body-file <本文のファイル>
```

- 親イシューがある場合は、ユーザーに確認してから、そのサブイシューに追加する。

```bash
gh api repos/<owner>/<repo>/issues/<親イシューの番号>/sub_issues -X POST -F sub_issue_id=<イシューのID>
```

- `<イシューのID>` は番号ではなく、`gh api repos/<owner>/<repo>/issues/<番号> -q .id` で得られる ID。

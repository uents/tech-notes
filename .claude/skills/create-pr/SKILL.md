# create-pr

## 1. 前提を確認する

- push と PR の作成は、ユーザーの指示があったときだけ行う。
- 現在のブランチが `main` でないことを確認する。
- `git status --short` で、コミットしていない変更がないことを確認する。
- `git log --oneline main..HEAD` で、PR に含まれるコミットを確認する。関係のないコミットが混ざっていないか見る。

## 2. push する

```bash
git push -u origin <ブランチ名>
```

## 3. PR を作成する

- ベースは `main` にする。
- タイトルは日本語で、変更の内容が分かるように書く。
- 本文は次の形にする。

```markdown
## Summary

- <変更点>

<Closes #<番号> または Refs #<番号>>

## Test plan

- [x] <実際に確認したこと>
- [ ] <確認していないこと>
```

- イシューへのリンクは、次のどちらかを選ぶ。
  - `Closes #<番号>`: PR でイシューの作業がすべて終わる場合（マージするとイシューがクローズされる）
  - `Refs #<番号>`: PR でイシューの作業の一部だけを行う場合（イシューはクローズされない）
- Test plan には、実際に実行して確認したことだけを `[x]` で書く。確認していないことは `[ ]` にするか、未確認と書く。
- 既存のエラーが残っている場合は、今回の変更で増えていないことを確認し、その旨を書く。

```bash
gh pr create --base main --title "<タイトル>" --body-file <本文のファイル>
```

- 作成後、PR の URL をユーザーに伝える。

## 4. マージ後に後片付けする

ユーザーからマージを知らされたら、次を行う。

```bash
git checkout main
git pull
git fetch --prune
git branch -d <ブランチ名>
```

- リモートのブランチ（`origin/<ブランチ名>`）が残っていれば、削除してよいかユーザーに確認してから `git push origin --delete <ブランチ名>` で削除する。
- 関係するイシューの状態とチェックリストを確認し、更新が必要ならユーザーに確認する。

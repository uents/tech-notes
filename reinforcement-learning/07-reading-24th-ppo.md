対象: ptcg-population-rl（24位の公開コード、Apache-2.0、コミット `9facfed`）の `src/agents/dragapult/ppo/`
参考: ptcg-abc の `docs/research/reproduce/24-population-rl.md`（実測と実装の調査）

## この章で説明できるようになること

- 収集・学習データの作成・更新の3つの処理が、それぞれ何をしているかを説明できる
- 教科書の式（advantage、重要度比、クリップ、価値の損失）が、どのコードに対応するかを指させる
- 実装が何を検査して、何を守っているかを説明できる

## 1. 全体の流れ

パスは `src/agents/dragapult/` からの相対。

```
ppo/scripts/run_cycle.py              1サイクルを通して回す
 ├── ppo/scripts/collect.py           C++ のアリーナで対局し、リプレイと統計を書き出す
 │    └── ppo/extract.py              リプレイを読み、学習データを作る。収集時との一致を検査する
 ├── ppo/scripts/train.py
 │    └── ppo/train.py                GPU で PPO の更新をする
 ├── transformer/scripts/export.py    C++ 用にモデルを書き出す
 └── transformer/scripts/validate.py  書き出したモデルの動作を確かめる
```

## 4. 実装が守っていること

- 収集時（C++）と学習時（Python）で、特徴量が一致すること（`ppo/extract.py`。絶対誤差と相対誤差の許容はどちらも2e-6）
- 収集時に記録した対数確率、価値、エントロピーが、収集に使ったモデルで計算し直した値と一致すること（`ppo/rollout.py` の `audit_behavior`。許容はどちらも2e-5）
- 複数選択の途中の状態（すでに選んだ手、合法手、選んだ手）が一致すること
- 収集に使ったモデルの ID と温度が、設定と一致すること
- 合法手が100を超えるとき、各プレイヤーの場（バトル場とベンチ）が6スロットを超えるときは、切り捨てずに例外にすること

なぜこれらが要るのかを、3章・4章の内容と結びつけて書く。

## 5. 動かして確かめる（案）

- 1サイクルだけ小さく回し、ログに出る値（KL、クリップされた割合、エントロピー、value_loss）を見る
- `calibrate.py` を実行し、学習率と KL の関係を確かめる
- 設定を1つだけ変えて回し、指標がどう動くかを見る（例: エントロピーの係数）

実行は計算資源を使うので、ptcg-abc 側のイシュー（#11）と合わせて計画する。
